PRESENTATION DU PROJET DOCKER

Mon projet contient une API FastAPI, une base PostgreSQL et deux interfaces
web : une en JavaScript et une en TypeScript. Docker permet de créer une image
pour chaque application ; Docker Compose les lance ensemble.

DOCKERFILE DU BACKEND

Le Dockerfile du backend utilise Python pour installer les dépendances et
lancer l'API avec Uvicorn. Il comporte deux stages :

1. base
- Installe les dépendances de production (requirements.txt).
- Crée l'utilisateur non-root fastapi.

2. runtime
- Part de base et copie uniquement le code de l'application.
- Lance l'API avec Uvicorn.

Les tests backend sont exécutés directement par pytest dans la CI ; ils ne
sont pas inclus dans l'image Docker de l'application.

DOCKERFILE DU FRONTEND JAVASCRIPT

Le navigateur peut lire directement le JavaScript : il n'y a pas besoin de
le compiler. Nginx sert les fichiers du site et écoute sur le port interne
8080.

DOCKERFILE DU FRONTEND TYPESCRIPT

Le TypeScript doit être compilé avant d'être utilisé par le navigateur. Le
Dockerfile a donc deux étapes : Node.js compile le projet, puis Nginx sert
les fichiers produits. L'image finale ne contient que Nginx et le site
compilé, pas Node.js ni les outils de build. Nginx écoute sur le port 80.

DOCKER COMPOSE

Compose lance PostgreSQL, l'API et les deux frontends. Il les relie sur le
réseau Docker et attend que PostgreSQL soit prêt avant de lancer l'API.
Un volume conserve les données de la base quand les conteneurs sont recréés.
Les frontends transmettent les requêtes /api au backend.

Les services sont accessibles depuis mon ordinateur :
- API : http://localhost:8001
- Frontend JavaScript : http://localhost:8083
- Frontend TypeScript : http://localhost:8084

Pour lancer l'application :
    docker compose up --build -d

Les tests backend sont lancés par la CI GitHub Actions avec pytest.
